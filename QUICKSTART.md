# Подключить свой ИИ к GymAssistant

Ваш ассистент сможет читать ваши тренировки и создавать планы с выданными вами правами.
Это внешний ассистент, не замена модели встроенного Джима. Токен GymAssistant — доступ
к вашему аккаунту, а не ключ или подписка на нейросеть.

## Что понадобится

- ИИ-приложение с поддержкой **локальных MCP-серверов (stdio)** и возможностью запускать программы.
  Обычное сообщение в браузерном чате само по себе ничего не устанавливает.
- Git и Python **3.14** (проверенная версия). Docker, .NET и доступ к GitHub Packages не нужны.
- Ваш аккаунт GymAssistant и Personal API Token: **Настройки → API-токены**.

Для первого подключения достаточно `profile:read`, `exercises:read`, `plans:read`,
`workouts:read`. Для замеров добавьте `body:read`, для Apple Health — `health:read`.
Для создания/дополнения планов добавьте `plans:write`; не выдавайте остальные права записи
без необходимости. Данные Health доступны только после синхронизации iPhone с аккаунтом.

## 1. Установка (macOS / Linux)

В терминале, из каталога для исходников:

```sh
git clone https://github.com/Gym-Assistant/GymAssistantMcpServer.git
cd GymAssistantMcpServer
python3 --version
python3 integrations/local-gymassistant/install.py "$HOME/.local/share/gymassistant-mcp"
python3 -m venv "$HOME/.local/share/gymassistant-mcp/.venv"
"$HOME/.local/share/gymassistant-mcp/.venv/bin/python" -m pip install -r "$HOME/.local/share/gymassistant-mcp/requirements.txt"
```

Проверьте, что `python3` действительно указывает на Python 3.14.
При повторной установке установщик сохраняет прежние модули в `.backups`,
а `.env`, существующий `run.sh` и данные пользователя не заменяет.

## 2. Сохранить токен локально

Следующая команда запрашивает токен скрыто и создаёт файл с правами только для владельца.
Токен не попадёт в историю команд. Существующий файл не перезаписывается.
Не отправляйте токен ассистенту в сообщении и не добавляйте его в Git.

```sh
python3 - <<'PY'
import getpass, os
from pathlib import Path
p = Path.home() / '.local/share/gymassistant-mcp/.env'
if p.exists():
    raise SystemExit('Файл уже существует; для замены токена откройте его локально в редакторе.')
token = getpass.getpass('Personal API Token GymAssistant: ').strip()
if not token.startswith('gma_') or any(c.isspace() for c in token):
    raise SystemExit('Нужен API-токен GymAssistant (gma_...).')
fd = os.open(p, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, 'w') as f:
    f.write('GYM_API_TOKEN=' + token + '\n')
print('Токен сохранён локально.')
PY
```

## 3. Подключить сервер в ИИ-приложении

Укажите локальную команду запуска, подставив **абсолютный путь** к вашему домашнему каталогу:

```json
{
  "mcpServers": {
    "gymassistant": {
      "command": "/Users/ВАШЕ_ИМЯ/.local/share/gymassistant-mcp/run.sh"
    }
  }
}
```

Это пример для клиентов с форматом `mcpServers`. Название файла и формат настроек
зависят от приложения; в клиентах с другим форматом задайте ту же команду запуска.
На Linux домашний каталог обычно `/home/ВАШЕ_ИМЯ`. Не используйте `~` в JSON-команде.
Переподключите сервер или перезапустите ИИ-приложение.
На Windows используйте абсолютный путь к `.venv\\Scripts\\python.exe`, а `server.py`
передайте аргументом; shell-обёртка `run.sh` для Windows не подходит. Windows здесь не проверена.

## 4. Проверка

Попросите ассистента:

> Подключись к GymAssistant. Вызови gym_me, проверь мой аккаунт и покажи мои планы
> через gym_plans. Пока ничего не создавай и не меняй.

Доступны **15 инструментов** этой версии: профиль, история тренировок, рекорды,
замеры, Health, личные и стандартные упражнения, чтение/создание/дополнение планов.
Это отличается от набора .NET MCP: у Python имена начинаются с `gym_`.

После проверки можно попросить:

> Подготовь план из упражнений общего каталога. Сначала покажи его мне,
> а после подтверждения создай через gym_create_plan. Не меняй прежние планы.

Коннектор работает только от имени владельца токена. Для другого человека нужен
его собственный токен в его локальной установке. Данные, прочитанные ассистентом,
могут передаваться выбранному вами ИИ-провайдеру — выдавайте только нужные права.

## Если не подключилось

- **401:** токен истёк, отозван или неверен. Создайте новый в приложении и замените локально.
- **403:** не хватает прав токена либо доступа аккаунта к функции. Не пытайтесь обойти ограничение.
- **Нет инструментов:** проверьте абсолютный путь, установленное окружение и перезапуск клиента.
- **Health пустой:** проверьте разрешения и синхронизацию iPhone; пустые данные — не нулевые значения.
- **Неясный результат записи / unknown / 500 / таймаут:** сначала прочитайте план по возвращённому ID;
  не повторяйте создание вслепую. При конфликте 409 перечитайте план.

Для диагностики без вывода персональных данных, из клона репозитория:

```sh
GYM_MCP_ENV_FILE="$HOME/.local/share/gymassistant-mcp/.env" \
  "$HOME/.local/share/gymassistant-mcp/.venv/bin/python" scripts/check-readonly.py \
  -- "$HOME/.local/share/gymassistant-mcp/run.sh"
```

Проверка только читает профиль, каталог, планы, последнюю тренировку и справочник Health.
Если `health:read` не выдан, соответствующая проверка может завершиться FAIL — это не повод
расширять права, если Health вам не нужен.

## Обновление и отключение

Обновляйте исходники через `git pull --ff-only`, затем повторяйте установку модулей
и зависимостей из шага 1 и переподключайте MCP. Если в клоне есть свои изменения,
сначала сохраните их; не применяйте `git reset --hard`.
Отключить доступ: отозвать токен в GymAssistant и убрать сервер из настроек ИИ-клиента.

## Docker-вариант

.NET MCP остаётся отдельным вариантом с более широким набором инструментов.
Выпуск `0.6.0` существует, но на проверке 03.11.2026 **анонимный доступ к образу GHCR
получил 401**. Не создавайте GitHub-токен ради первого подключения: используйте путь выше.
Кроме того, .NET 0.6.0 падает при чтении силовых подходов с `measurement: null`.
Python-путь выше проверен на этих текущих данных. Исправление и новый выпуск .NET
остаются отдельным открытым пунктом; открытие registry само по себе его не исправит.
