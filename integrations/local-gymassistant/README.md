# Локальный MCP GymAssistant

Фактически подключённый в Codex сервер запускается из `~/tools/gymassistant-mcp/run.sh`. Он независим от Docker-образа .NET MCP. Локальные модули добавляют чтение Apple Health, просмотр и создание личных планов и дополнение их днями, сохраняя прежние инструменты.

## Установка

Сначала сохранить резервную копию `server.py` и `run.sh`. Скопировать `health_tools.py` рядом с `server.py`. Перед блоком запуска добавить:

```python
from health_tools import register_health_tools
register_health_tools(mcp, _api_get)
```

Используется уже настроенный `GYM_API_TOKEN`. Для отдельного узкого доступа можно задать `GYM_HEALTH_API_TOKEN` с правами `profile:read` и `health:read`, сохранив основной токен. Тогда обёртка `_api_get` принимает необязательный аргумент `token`, а регистрация выглядит так:

```python
from health_tools import register_health_tools, same_account_reader
health_token = _ENV.get("GYM_HEALTH_API_TOKEN")
health_reader = same_account_reader(
    _api_get, lambda path, params=None: _api_get(path, params, health_token)
) if health_token else _api_get
register_health_tools(mcp, health_reader)
```

`same_account_reader` перед чтением сопоставляет владельцев обоих токенов через `/auth/me` и не позволяет смешать Health другого аккаунта с тренировками. Токен должен принадлежать тому же аккаунту, что импортирует Health, и иметь отдельное право `health:read`. Старые токены не расширяются автоматически. Не записывать токен в репозиторий или журнал.

После установки переподключить MCP в клиенте: существующий процесс не перечитывает исходники. Проверка только через импорт Python не заменяет `initialize`, `tools/list` и настоящий `tools/call` в новом stdio-процессе.

## Проверка

Запустить `python -m unittest discover -s integrations/local-gymassistant -v` окружением с MCP SDK. Проверяются диапазон дат, отсутствие запросов при неправильном диапазоне, сохранение null и свежести данных. Серверные проверки дополнительно покрывают авторизацию, разделение аккаунтов и повторный импорт.

Для проверки установленного процесса: `python integrations/local-gymassistant/verify_stdio.py /absolute/path/to/run.sh`. Проверка использует локальный синтетический API и тестовый PAT, не обращается к production.

## Создание личного плана

В локальный сервер можно добавить `plan_tools.py`, не заменяя его прежние инструменты или ключ. Установка с резервной копией:

```bash
python integrations/local-gymassistant/install_plans.py ~/tools/gymassistant-mcp
```

Установщик сохраняет `server.py`, `run.sh`, `health_tools.py` и предыдущий модуль планов в `.backups/plans-*`; текущий Health-модуль не перезаписывает. Для отката восстановить `server.py` из указанной копии и переподключить клиент. Если модуль планов был установлен раньше, восстановить и его копию.

После установки переподключить MCP в клиенте. Новые инструменты:

- `gym_exercises` — получить личные `id` или базовые `globalId`;
- `gym_plans`, `gym_plan` — проверить имеющиеся личные планы;
- `gym_create_plan` — записать согласованный **новый** план целиком: дни, упражнения, подходы, разминка, вес, отдых и комментарии.

Для создания нужны существующие права `profile:read`, `exercises:read`, `plans:write`; для предварительного просмотра и проверки — `plans:read`. Инструмент не меняет права и не создаёт ключей. Все новые IDs формируются самостоятельно, старый план этим методом заменить нельзя. План остаётся личным и не назначается активным. При таймауте или 5xx результат `unknown` содержит `plan_id`: сначала проверить этот ID через `gym_plan`, не повторять создание вслепую.

Проверки:

```bash
~/tools/gymassistant-mcp/.venv/bin/python -m unittest discover -s integrations/local-gymassistant -v
~/tools/gymassistant-mcp/.venv/bin/python integrations/local-gymassistant/verify_plans_stdio.py
```

Вторая команда запускает временную копию текущего сервера на синтетическом API с тестовым токеном. Production для тестирования не используется.


## Добавление дней в существующий план

`gym_append_plan_days(plan_id, expected_updated_at, days)` передаёт только новые дни в `POST /plans/{id}/days`. Нужен backend 0.16.0 или новее с этим маршрутом. Старые ID, параметры, комментарии и дни не передаются в заменяющее сохранение.

Перед вызовом прочитать план через `gym_plan` и скопировать его `updatedAt` в `expected_updated_at`. Сервер под блокировкой проверяет владельца и актуальность, затем вставляет новые строки. При 409 перечитать план. При потере ответа проверить возвращённые `added_day_ids`; повторного POST внутри инструмента нет.

Перед каждым изменением сохраняется JSON с полным исходным планом и добавлением в `~/Library/Application Support/GymAssistant/McpBackups` (файл 0600). Путь можно переопределить `GYM_PLAN_BACKUP_DIR` для изолированного теста. Если запись копии не удалась, запрос не отправляется. Копия личная: не коммитить и не публиковать. Восстановление содержимого — отдельное согласованное действие, автоматического отката данных нет.

Дни плана являются шаблонами: добавление не создаёт выполненные тренировки и не назначает календарные даты. Старые клиенты по-прежнему используют полное сохранение плана; их параллельное устаревшее сохранение после добавления не меняется этим новым API.

## Дополнительные измерения — GA-043

Для нового формата нужен backend **0.17.1 или новее**, контракт которого содержит
`SetMeasurement`. До подтверждения серверного выпуска локальный модуль не устанавливать:
старый сервер может проигнорировать неизвестные поля.

`gym_create_plan` и `gym_append_plan_days` принимают `sets[].measurement`:

```json
{
  "measurement": {
    "trackingType": "cardio",
    "durationSeconds": 1200,
    "distanceMeters": 3000,
    "inclinePercent": 2
  }
}
```

Поддерживаются `weight_reps`, `bodyweight_reps`, `assisted_reps`, `band_reps`,
`duration`, `cardio`, `weight_distance`, `interval`. Измерения передаются в единицах API:
секунды, метры, килограммы помощи, сантиметры высоты. Поле `unit` по-прежнему относится
к прежнему `weight`, его значения не пересчитываются. Для времени/дистанции/интервалов
повторы не обязательны; прежний подход без `measurement` по-прежнему требует повторы.

Чтение `gym_workout`/`gym_workouts` возвращает `measurement` полностью, включая будущие
неизвестные поля. Формат упражнения возвращается как `trackingType`, но не меняет смысл
старых подходов. Объём и рекорды рассчитываются только для прежних подходов без
`measurement` либо явного `weight_reps`; кардио/интервалы/неизвестные форматы в 1RM
не попадают. Поле `top` равно `null`, если силовых подходов нет.

Установщик дополнительно ставит `workout_tools.py` и заменяет только тела двух функций
локального сервера (`_summarize_workout`, `gym_records`) делегированием этому модулю.
Имена, сигнатуры и описания прежних команд сохраняются. Неизвестные сигнатуры отклоняются.
Копия включает все изменяемые файлы; для отката вернуть `server.py`, `plan_tools.py` и,
если он был, `workout_tools.py` из той же копии, затем переподключить MCP. Ключи,
`run.sh` и Health не изменяются.
