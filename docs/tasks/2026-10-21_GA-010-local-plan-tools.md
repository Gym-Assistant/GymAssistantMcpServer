# GA-010 — создание планов через подключённый MCP Mentoru

## Контекст
Владелец показал ответ Mentoru об отсутствии создания планов и уточнил, что права ключа уже выданы. Требуется исправить фактически подключённую интеграцию, сохранив существующие доступы и данные.

## Текущее состояние
Codex запускает `~/tools/gymassistant-mcp/run.sh`, локальный Python FastMCP с девятью инструментами чтения. В .NET MCP `create_plan` уже существует, но этот сервер здесь не подключён. Право ключа само по себе не добавляет инструмент в `tools/list`.

Действующий ключ успешно читает `/auth/me`, `/plans` и `/exercises`. Права записи read-only проверкой не подтверждены: API списка scopes доступно только через JWT. Не делались пробные POST в production, ротация или изменение прав.

## План и реализация
- Дополнить локальный сервер четырьмя инструментами: `gym_plans`, `gym_plan`, `gym_exercises`, `gym_create_plan`.
- Для создания использовать типизированные дни, упражнения и подходы. Личные ссылки — `id`, базовые — `globalId`; имена берутся из соответствующего каталога.
- Сохранять веса/единицы, повторы, разминку, отдых, RPE и комментарии упражнения. Все идентификаторы нового дерева генерировать внутри инструмента: API сервера выполняет upsert, поэтому существующий ID извне не принимается.
- Проверять доступность упражнений до записи. Не публиковать план и не назначать его активным.
- POST не повторять автоматически. При потере ответа или HTTP 5xx вернуть неопределённый результат и ID для проверки чтением. Не выдавать ошибку за успешное сохранение.
- Сохранить исходники локального сервера до установки; ключ, env, Health и прежние инструменты оставить без изменений.

## Следующий шаг
Переподключить GymAssistant MCP в открытом чате Mentoru: существующая сессия по-прежнему видит девять старых инструментов. Управление окном Codex инструменту компьютера недоступно; переподключение не подтверждено. После него бот сможет создать ранее согласованный план отдельным запросом владельца. Запись именно этим ключом проверяется только при таком реальном согласованном действии, а не тестом в личном аккаунте.

## Границы
Backend, БД, MAUI и реальные планы владельца не меняются. Поэтому миграция и бэкап production-БД не требуются; резервируется именно изменяемое локальное подключение. Существующий процесс MCP не перечитывает Python-файлы: новый набор инструментов появляется после переподключения клиента. Проверка нового процесса не означает, что старая сессия Mentoru уже обновила список.


## Продолжение: добавление дней — подготовлено, ещё не установлено

Владелец показал, что Mentoru уже умеет создавать планы, но не может дописать оставшиеся семь дней в тот же план. Подготовлен `gym_append_plan_days(plan_id, expected_updated_at, days)` через отдельный серверный append API. Он повторно использует существующий pool, передаёт только новые строки, сохраняет локальную копию до POST и проверяет неизменность старого дерева в ответе. При конфликте/таймауте/ошибке повтор не выполняется; для проверки возвращаются новые ID.

35 Python unit PASS, настоящий stdio: девять прежних схем и пять инструментов планов; создание 2 дней и добавление 7 проверены, четыре резервных копии проверены до POST, Health прежний. Установщик обновления 3→4 аргумента и откат исходника проверены в временном каталоге. Реальный установленный MCP остаётся с 13 инструментами, добавление ещё не включено до выпуска серверного маршрута.

Backend-кандидат прошёл полный набор 358 интеграционных тестов, включая 1→8 дней и конкурентное добавление. Производственные данные не менялись. Дни плана — шаблоны, не календарные тренировки.
