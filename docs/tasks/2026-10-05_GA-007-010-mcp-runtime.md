# GA-007/009/010 — согласованный MCP и реальный stdio

## Контекст и текущее состояние

MCP main84a9ad3 использует плавающие версии с locked restore, Linux glibc RID с Alpine runtime. Локальная старая настройка GitHub Packages вернула401 на чистом Docker restore; cached .NET restore не доказывает наличие доступа к registry.

## Выполнено локально

- Зафиксированы реальные ModelContextProtocol1.3.0 / Hosting,Http10.0.8 / GymAssistant.Client0.7.0; lockfiles получены штатным restore. Пользовательский `packages.lock 2.json` не изменяется и не включается в commit.
- Runtime приведён к glibc и штатному non-root APP_UID. Package credentials передаются только на время restore через environment из BuildKit secrets; не сохраняются в NuGet.Config слоя сборки.
- Найден воспроизводимый реальный дефект: health_check запрашивал `/api/api/auth/me` вместо `/api/auth/me`. API-root передаётся с одним префиксом; поддерживаются root URL, `/api/` и reverse-proxy prefix.
- Build0errors/0warnings PASS;15 тестов PASS, включая реальный NSwag запрос и PAT через HttpClientFactory.
- Стандартный stdio процесс: initialize,40 tools,health_check,profile PAT и ping PASS на синтетическом backend. Рабочая БД/реальный токен не использовались.
- Linux self-contained publish PASS. Его выполнение в runtime-deps Linux под UID1654:initialize/40 tools/health_check/ping PASS. Это не успешная чистая Docker сборка.
- CI готовится проверять stdio как обычного процесса, так и построенного Docker image; явные permissions contents:read/packages:read, locked restore, временные secret-файлы удаляются trap.

## Осталось

Получить фактический результат CI на текущем кандидате, включая чистый Docker restore/build и stdio. При package401 требуется исправить доступ registry, а не подменять пакет. Сведение main/релиз пока не выполнены. CLI Claude на ноутбуке отсутствует; ручная проверка через него не заявляется. Реальный stdio проверяет транспорт напрямую по [спецификации MCP](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports).
